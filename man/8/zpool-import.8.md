# zpool-import(8)

## 名称

`zpool-import` — 导入 ZFS 存储池或列出可用的存储池

## 概述

```sh
zpool import [-D] [-d 目录|设备]…
```

```sh
zpool import -a [-DflmMN] [-F [-nTX]] [--rewind-to-checkpoint] [-c 缓存文件|-d 目录|设备] [-o 挂载选项] [-o 属性=值]… [-R 根目录]
```

```sh
zpool import [-DflmMt] [-F [-nTX]] [--rewind-to-checkpoint] [-c 缓存文件|-d 目录|设备] [-o 挂载选项] [-o 属性=值]… [-R 根目录] [-s] 池名|标识符 [新池名]
```

## 说明

### `zpool import [-D] [-d dir|device]…`

列出可供导入的存储池。如果未指定 `-d` 或 `-c` 选项，该命令会在 Linux 上使用 libblkid、在 FreeBSD 上使用 geom 搜索设备。`-d` 选项可以指定多次，此时会搜索所有目录。如果设备看起来属于某个已导出的池，该命令会显示该池的摘要，其中包括池名、数字标识符，以及每个设备或文件的 vdev 布局与该设备的当前健康状况。除非指定 `-D` 选项，否则不会列出已销毁的池（即此前用 `zpool destroy` 命令销毁的池）。

数字标识符是唯一的，当有多个同名的已导出池可用时，可以用它代替池名。

#### `-c cachefile`

从给定的 `cachefile` 读取配置，该文件由 `cachefile` 池属性创建。此时使用该 `cachefile`，而不搜索设备。

#### `-d dir|device`

使用 `device`，或在 `dir` 中搜索设备或文件。`-d` 选项可以指定多次。

#### `-D`

仅列出已销毁的池。

### `zpool import -a [-DflmMN] [-F [-nTX]] [--rewind-to-checkpoint] [-c cachefile|-d dir|device] [-o mntopts] [-o property=value]… [-R root] [-s]`

导入在搜索目录中找到的所有池。该命令与上一条命令相同，区别在于它会导入所有可用设备数量充足的池。除非指定 `-D` 选项，否则不会导入已销毁的池（即此前用 `zpool destroy` 命令销毁的池）。

#### `-a`

搜索并导入找到的所有池。

#### `-c cachefile`

从给定的 `cachefile` 读取配置，该文件由 `cachefile` 池属性创建。此时使用该 `cachefile`，而不搜索设备。

#### `-d dir|device`

使用 `device`，或在 `dir` 中搜索设备或文件。`-d` 选项可以指定多次。此选项与 `-c` 选项不兼容。

#### `-D`

仅导入已销毁的池。同时必须指定 `-f` 选项。

#### `-f`

强制导入，即使池看起来可能仍处于活动状态。

#### `-F`

恢复模式，用于无法导入的池。尝试丢弃最近的若干事务，使池恢复到可导入状态。并非所有损坏的池都能通过此选项恢复。如果恢复成功，被丢弃事务中的数据将不可挽回地丢失。如果池可导入或已导入，则忽略此选项。

#### `-l`

表示该命令在使池上线时，会为其尝试挂载的所有加密数据集请求加密密钥。注意，如果有任何数据集的 `keylocation` 为 `prompt`，该命令会阻塞，等待输入密钥。不指定此标志时，加密数据集在密钥加载之前将一直不可用。

#### `-m`

允许在日志设备缺失时导入池。由于日志设备会被丢弃，最近的事务可能丢失。

#### `-M`

允许即使存在对池运行并不关键的损坏元数据也能成功导入，例如文件或目录的间接块，或者一块 dnode。受影响的对象将变得无法访问，其空间会泄漏，并且可能无法删除。不指定此选项时，此类损坏会导致池无法导入。**警告**：此选项可能对池的健康造成极大危害，仅应作为最后手段使用。

#### `-n`

与 `-F` 恢复选项配合使用。用于判断无法导入的池能否再次变为可导入，但不会实际执行池恢复。有关池恢复模式的更多详情，参见上文的 `-F` 选项。

#### `-N`

导入池，但不挂载任何文件系统。

#### `-o mntopts`

挂载池中的数据集时要使用的挂载选项列表，以逗号分隔。有关数据集属性与挂载选项的说明，参见 zfs(8)。

#### `-o property=value`

在导入的池上设置指定的属性。有关可用池属性的更多信息，参见 zpoolprops(7) 手册页。

#### `-R root`

将 `cachefile` 属性设为 `none`，并将 `altroot` 属性设为 `root`。

#### `--rewind-to-checkpoint`

将池回退到检查点状态。一旦使用此标志导入池，就无法撤销回退。检查点之后写入的所有更改与数据都会丢失！唯一的例外是启用了 `readonly` 挂载选项的情况。此时会以检查点状态打开池，管理员可以查看完全回退后池会呈现的样子。

#### `-s`

使用默认搜索路径扫描，不会查询 libblkid 缓存。可以通过设置 `ZPOOL_IMPORT_PATH` 环境变量来指定自定义搜索路径。

#### `-X`

与 `-F` 恢复选项配合使用。用于判断是否采取极端措施来寻找有效的 txg。这允许把池回滚到一个不再保证一致的 txg。在不一致的 txg 上导入的池可能包含无法纠正的校验和错误。有关池恢复模式的更多详情，参见上文的 `-F` 选项。**警告**：此选项可能对池的健康造成极大危害，仅应作为最后手段使用。

#### `-T`

指定用于回滚的 txg。隐含 `-FX`。有关池恢复模式的更多详情，参见上文的 `-X` 选项。**警告**：此选项可能对池的健康造成极大危害，仅应作为最后手段使用。

### `zpool import [-DflmMt] [-F [-nTX]] [--rewind-to-checkpoint] [-c cachefile|-d dir|device] [-o mntopts] [-o property=value]… [-R root] [-s] pool|id [newpool]`

导入指定的池。可以通过池名或数字标识符来标识池。如果指定了 `newpool`，则使用名称 `newpool` 导入该池；否则，将使用其导出时的名称导入。

如果设备在没有先运行 `zpool export` 的情况下从系统中移除，该设备会显示为可能仍处于活动状态。此时无法判断这是一次失败的导出，还是该设备确实正被另一台主机使用。要导入处于这种状态的池，必须指定 `-f` 选项。

## 示例

### 示例 9：导入 ZFS 存储池

以下命令显示可用的池，然后导入池 `tank` 供系统使用。该命令的结果与以下内容类似：

```sh
# zpool import
  pool: tank
    id: 15451357997522795478
 state: ONLINE
action: The pool can be imported using its name or numeric identifier.
config:

        tank        ONLINE
          mirror    ONLINE
            sda     ONLINE
            sdb     ONLINE

# zpool import tank
```
