# zfs-send(8)

## 名称

`zfs-send` — 为 ZFS 数据集生成备份流

`zfs-redact(8)` 是 `zfs-send(8)` 的历史别名。

## 概述

```sh
zfs send [-DLPUVbcehnpsvw] [-R [-X dataset [, dataset]…]] [[-I | -i] snapshot] snapshot
```

```sh
zfs send [-DLPVcensvw] [-i snapshot | bookmark] filesystem | volume | snapshot
```

```sh
zfs send -redact redaction_bookmark [-DLPVcenpv] [-i snapshot | bookmark] snapshot
```

```sh
zfs send [-PVenv] -t receive_resume_token
```

```sh
zfs send [-PVnv] -S filesystem
```

```sh
zfs redact snapshot redaction_bookmark redaction_snapshot …
```

## 说明

### `zfs send [-DLPUVbcehnpsvw] [-R [-X dataset [, dataset]…]] [[-I | -i] snapshot] snapshot`

为第二个 `snapshot` 生成一个流表示，并写入标准输出。该输出可以重定向到文件，也可以发送到另一台系统（例如通过 ssh(1)）。默认生成完整流。

#### `-D`、`--dedup`

去重发送已不再支持。此标志仅为向后兼容而保留，实际会生成常规的、非去重流。

#### `-I snapshot`

生成一个流包，从第一个 `snapshot` 到第二个 `snapshot` 发送其间的所有中间快照。例如，`-I @a fs@d` 相当于 `-i @a fs@b ; -i @b fs@c ; -i @c fs@d`。增量源可以像 `-i` 选项那样指定。

#### `-L`、`--large-block`

生成可能包含大于 128 KiB 块的流。如果禁用了 `large_blocks` 池特性，或者该文件系统从未包含过大于 128 KiB 的块，此标志不起作用。请注意，激活按数据集的 `large_blocks` 特性并使此标志生效的是写入这类块，而不是设置 `recordsize` 属性。接收方系统也必须启用 `large_blocks` 池特性。如果 `large_microzap` 池特性处于启用状态，则必须使用此标志。

在没有使用此标志的情况下复制包含大块的文件系统，会在接收方一侧将其拆分为 128 KiB 的块，因此接收到的副本不会激活 `large_blocks` 特性。此后两份副本的物理块布局各不相同，而在相反方向发回的增量流会被拒绝，因为该流无法携带原始文件系统仍然拥有的大块。要从这种情况恢复，需要向一个新数据集执行一次完整接收。如果复制方向有可能反转，请从第一次复制起就使用此标志。有关 ZFS 特性标志和 `large_blocks` 特性的详细信息，参见 zpool-features(7)。

#### `-P`、`--parsable`

打印关于所生成流包的、机器可解析的详细信息。

#### `-R`、`--replicate`

生成一个复制流包，将复制指定的文件系统及其所有后代文件系统，直到指定的快照为止。接收时，所有属性、快照、后代文件系统和克隆都会得到保留。

如果使用 `-i` 或 `-I` 标志配合 `-R` 标志，则会生成增量复制流。接收该流时会设置属性的当前值，以及快照和文件系统的当前名称。如果在接收该流时指定 `-F` 标志，发送方不存在的快照和文件系统会被销毁。如果使用 `-R` 标志发送加密数据集，则还必须指定 `-w` 或 `-U`。

#### `-V`、`--proctitle`

将进程标题设置为按秒报告的已发送数据量。

#### `-X`、`--exclude dataset [, dataset]…`

配合 `-R` 使用时，`-X` 指定一组要从发送流中排除的数据集（因此也包括其后代）。根数据集不能被排除。`-X a -X b` 等同于 `-X a, b`。

#### `-e`、`--embed`

对由 `embedded_data` 池特性以更紧凑方式保存在磁盘上的块使用 `WRITE_EMBEDDED` 记录，从而生成更紧凑的流。如果禁用了 `embedded_data` 特性，此标志不起作用。接收方系统必须启用 `embedded_data` 特性。如果发送方系统上 `lz4_compress` 或 `zstd_compress` 特性处于启用状态，则接收方系统也必须启用相应的特性。使用此标志发送的数据集可能无法作为加密数据集接收，因为加密数据集不能使用 `embedded_data` 特性。有关 ZFS 特性标志和 `embedded_data` 特性的详细信息，参见 zpool-features(7)。

#### `-b`、`--backup`

仅发送已接收的属性值，不论这些值是否被本地设置覆盖，但前提是该数据集曾被接收过。当你希望 `zfs receive` 恢复已发送到数据集上备份的已接收属性，并避免发送那些可能与源数据集毫无关系、仅与数据备份方式有关的本地设置时，使用此选项。

#### `-c`、`--compressed`

对磁盘和内存中已压缩的块使用压缩的 `WRITE` 记录，从而生成更紧凑的流（详见 `compression` 属性）。如果发送方系统上 `lz4_compress` 或 `zstd_compress` 特性处于启用状态，则接收方系统也必须启用相应的特性。如果发送方系统启用了 `large_blocks` 特性，但在配合 `-c` 使用时未提供 `-L` 选项，则数据在发送前会被解压，以便拆分为更小的块大小。使用 `-c` 发送的流，其数据在接收方一侧不会通过 `-o compress = value` 重新压缩。数据将保持发送方原来的压缩状态。新的压缩属性只对未来写入的数据生效。注意，除非你指定 `-o compress = off`，否则来自发送方的未压缩数据仍会尝试在接收方压缩。

#### `-w`、`--raw`

对于加密数据集，按磁盘上的原样发送数据。即使加密密钥当前未加载，也可以完成备份。此后该备份可以在一台不受信任的机器上接收，因为那台机器没有可用于读取受保护数据或篡改数据而不被发现的加密密钥。接收后，数据集将具有与发送方相同的加密密钥，不过如果未另行提供，`keylocation` 属性将默认为 `prompt`。对于未加密的数据集，此标志等同于 `-Lec`。请注意，如果你不使用此标志发送加密数据集，数据将以未加密方式发送，并可能在接收方系统上使用不同的加密密钥重新加密，这将导致无法再对增量流向该系统执行 raw 发送。

#### `-h`、`--holds`

生成一个流包，包含所有的快照保留（由 `zfs hold` 命令创建），并指示 `zfs receive` 在接收方系统上对该数据集应用这些保留。

#### `-i snapshot`

从第一个 `snapshot`（即增量源）到第二个 `snapshot`（即增量目标）生成增量流。增量源可以指定为快照名称的最后组成部分（`@` 字符及其后面的内容），并假定它与增量目标属于同一个文件系统。

如果目标是克隆，则增量源可以是原始快照，而且必须完整指定（例如 `pool/fs@origin`，而不能只写 `@origin`）。

#### `-n`、`--dryrun`

执行一次空操作（No-op）的模拟发送。不生成任何实际发送数据。此选项与 `-v` 或 `-P` 标志配合使用时很有用，可以用来确定将发送哪些数据。此时，详细信息输出会写入标准输出（与之相反的是，非模拟发送时流写入标准输出，而详细信息输出写入标准错误）。

#### `-p`、`--props`

将数据集的属性包含在流中。指定 `-R` 时隐式包含此标志。接收方系统也必须支持此特性。使用此标志时，加密数据集的发送必须使用 `-w` 或 `-U`。

#### `-s`、`--skip-missing`

即使层次结构中存在缺失的快照，也允许发送复制流。当某个快照缺失时，不会抛出错误并中止发送，而是将警告打印到标准错误流，并跳过该快照所属的数据集及其后代。此标志只能与 `-R` 配合使用。

#### `-U`、`--no-preserve-encryption`

允许发送带有属性的加密数据集，但不保留加密。指定此标志时，原本会被阻止发送的加密数据集将以未加密数据的形式发送。

#### `-v`、`--verbose`

打印关于所生成流包的详细信息。这些信息包括按秒报告的已发送数据量。无论是否指定 `-v`，都可以通过发送 `SIGINFO` 或 `SIGUSR1` 请求相同的报告。

流的格式是确定的。你将能够在未来版本的 ZFS 上接收你的流。

### `zfs send [-DLPVcensvw] [-i snapshot | bookmark] filesystem | volume | snapshot`

生成一个发送流，其对象可以是文件系统，也可以是从书签开始的增量流。如果目标是文件系统或卷，则池必须为只读，或者该文件系统必须未挂载。当从文件系统或卷生成的流被接收时，默认的快照名称为 `--head--`。

#### `-D`、`--dedup`

去重发送已不再支持。此标志仅为向后兼容而保留，实际会生成常规的、非去重流。

#### `-L`、`--large-block`

#### `-P`、`--parsable`

打印关于所生成流包的、机器可解析的详细信息。

#### `-c`、`--compressed`

对磁盘和内存中已压缩的块使用压缩的 `WRITE` 记录，从而生成更紧凑的流（详见 `compression` 属性）。如果发送方系统上 `lz4_compress` 或 `zstd_compress` 特性处于启用状态，则接收方系统也必须启用相应的特性。如果发送方系统启用了 `large_blocks` 特性，但在配合 `-c` 使用时未提供 `-L` 选项，则数据在发送前会被解压，以便拆分为更小的块大小。

#### `-e`、`--embed`

#### `-i snapshot | bookmark`

生成增量发送流。增量源必须是目标历史中较早的一个快照。它通常位于目标文件系统自身的历史中，这种情况下可以指定为名称的最后组成部分（`#` 或 `@` 字符及其后面的内容）。

如果增量目标是克隆，则增量源可以是原始快照，也可以是原始文件系统中更早的快照，或者是原始快照的原始快照，依此类推。

#### `-n`、`--dryrun`

执行一次空操作（No-op）的模拟发送。不生成任何实际发送数据。此选项与 `-v` 或 `-P` 标志配合使用时很有用，可以用来确定将发送哪些数据。此时，详细信息输出会写入标准输出（与之相反的是，非模拟发送时流写入标准输出，而详细信息输出写入标准错误）。

#### `-v`、`--verbose`

打印关于所生成流包的详细信息。这些信息包括按秒报告的已发送数据量。无论是否指定 `-v`，都可以通过发送 `SIGINFO` 或 `SIGUSR1` 请求相同的报告。

### `zfs send -redact redaction_bookmark [-DLPVcenpv] [-i snapshot | bookmark] snapshot`

生成一个遮蔽发送流。该发送流包含正在发送的快照中、所有未被 `-redact`（或 `-d`）标志所指定的书签中的遮蔽列表所包含的块。相对于 `-redact` 标志所指定的书签创建时所针对的那些快照，所生成的发送流被称为已被遮蔽。该书签必须通过对正在发送的快照运行 `zfs redact` 命令来创建。

此功能可用于在远程系统上提供某个文件系统的克隆，而其父文件系统无需（或不便）可用。例如，如果一个文件系统包含敏感数据，并且它有若干个克隆，在这些克隆中该敏感数据已被保护或替换为虚拟数据，那么可以使用遮蔽发送来复制这些受保护的数据，而不会复制原始的敏感数据，同时仍然共享所有能够共享的块。就某一组快照而言已被遮蔽的快照，将包含该组中至少一个快照引用的所有块，但不包含该组中没有任何快照引用的块。换言之，如果该组中的所有快照都修改了父数据集中的某个块，则该块不会被发送；但如果其中有一个或多个快照没有修改父数据集中的某个块，它们仍然会引用父数据集中的该块，因此该块会被发送。注意，只有用户数据会被遮蔽。

接收遮蔽发送流时，会生成一个已遮蔽快照。由于遮蔽的特性，遮蔽数据集只能以以下方式使用：

1. 作为克隆接收增量发送：从原始快照到其遮蔽时所针对的那组快照中的某一个的增量发送。在这种情况下，该流被接收时会生成一个有效数据集，因为父数据集中被遮蔽的所有块都保证存在于子数据集的发送流中。此用法将生成一个常规快照，可以与其他快照一样使用。
2. 接收增量发送：从原始快照到某个对象的增量发送，而该对象是相对于初始快照遮蔽时所针对的那组快照的一个子集进行遮蔽的。在这种情况下，原始数据集中被遮蔽的每个块仍然处于被遮蔽状态（相对于更多快照进行遮蔽，会导致被遮蔽的数据更少，因为快照定义了哪些内容被允许，其余内容一律被遮蔽）。此用法将生成一个新的已遮蔽快照。
3. 接收增量发送：从原始快照的一个遮蔽书签开始的增量发送，而该遮蔽书签是在相对于初始快照遮蔽时所针对的那组快照的一个子集（而非其他任何对象）进行遮蔽时创建的。来自这种遮蔽书签的发送流将包含所有用于补全任何被遮蔽数据的必要块，如果需要的话，因为发送方系统知道哪些块最初被遮蔽。这将生成一个常规快照或一个遮蔽快照，取决于新的发送流是否已被遮蔽。
4. 接收增量发送：来自初始快照的一个遮蔽版本的增量发送，而该遮蔽版本是相对于初始快照遮蔽时所针对的那组快照中的某个对象进行遮蔽的。来自一个兼容的遮蔽数据集的发送流将包含所有用于补全任何被遮蔽数据的必要块。这将生成一个常规快照或一个遮蔽快照，取决于新的发送流是否已被遮蔽。
5. 作为已遮蔽快照的克隆接收完整发送。由于该流是完整发送，按定义它包含了创建新数据集所需的所有数据。此用法将生成一个常规快照或一个遮蔽快照，取决于该完整发送流是否已被遮蔽。

这些限制由 `zfs receive` 检测并强制执行；遮蔽发送流会包含该流所针对进行遮蔽的快照列表。这些快照信息会与已遮蔽快照一同保存，并用于检测及正确处理上述情形。注意，出于技术原因，目前无法将 raw 发送与遮蔽发送结合使用。

### `zfs send [-PVenv] -t receive_resume_token`

创建一个用于恢复中断接收的发送流。`receive_resume_token` 是正在接收的目标文件系统或卷上该属性的值。更多详情参见 `zfs receive -s` 的说明。

### `zfs send [-PVnv] -S filesystem`

从一个部分接收的数据集生成发送流。

#### `-S`、`--saved`

此标志要求指定的文件系统先前接收过一次未完成的、可恢复的发送，且该发送已被中断。在此类场景中，此标志使用户能够发送这种部分接收的状态。使用此标志时，如果存在最后完全接收的快照，将始终以它作为增量源。

### `zfs redact snapshot redaction_bookmark redaction_snapshot …`

生成一个新的遮蔽书签。除了常规的书签信息外，遮蔽书签还包含被遮蔽块的列表，以及所指定的遮蔽快照列表。被遮蔽的块是指快照中未被任何遮蔽快照引用的块。这些块通过对每个遮蔽快照中的元数据迭代、以确定自目标快照以来发生了哪些更改，从而找到。Redaction 旨在支持遮蔽的 zfs 发送；有关此操作目的的信息，参见 `zfs send` 的条目。如果遮蔽操作在中途中断（由于错误或系统故障），可以通过重新运行同一命令来恢复。

### 遮蔽（Redaction）

ZFS 支持数据子集化的一个有限版本，即遮蔽。使用 `zfs redact` 命令，可以创建一个遮蔽书签，用于保存包含敏感信息的块列表。将其提供给 `zfs send` 时，会触发一次遮蔽发送。遮蔽发送会省略包含敏感信息的块，并用 `REDACT` 记录替换它们。接收这些发送流时，会创建一个遮蔽数据集。遮蔽数据集由于内容不完整，默认无法挂载。它可以用于接收其他发送流。通过这种方式，数据集可用于数据备份和复制，享有 `zfs send` 与 `zfs receive` 所提供的一切好处，同时保护敏感信息不被存储到信任度较低的机器或服务上。

就遮蔽而言，整个过程分为两步：遮蔽步骤与发送/接收步骤。首先，创建一个遮蔽书签。这通过向 `zfs redact` 命令提供一个父快照、一个待创建的书签，以及若干个遮蔽快照来完成。这些遮蔽快照必须是父快照的后代，并且它们应该以某种方式修改被认为是敏感的数据。被所有遮蔽快照修改的任何数据块都会列在遮蔽书签中，因为它代表真正敏感的信息。到了发送步骤，发送过程不会发送遮蔽书签中列出的块，而是用 `REDACT` 记录替换它们。在目标系统上接收时，这将创建一个遮蔽数据集，其中缺少与发送方系统中遮蔽书签内块相对应的数据。随后还可以将原始父快照到各遮蔽快照的增量发送流接收在目标系统上，这将产生一个可正常使用的完整快照。从父文件系统中的某个快照到另一个快照的增量传输，也可以通过从遮蔽书签发送、而不是从快照本身发送来实现。

为了使该功能的用途更加清晰，下面给出一个示例。假设有一个 ZFS 文件系统，其中包含四个文件，这些文件代表某个在线购物服务的信息。其中一个文件包含用户名和密码列表，另一个包含购买历史，第三个包含点击跟踪数据，第四个包含用户偏好。这些数据的所有者希望将其提供给开发团队用于测试，并提供给市场研究团队用于分析。开发团队需要用户偏好和点击跟踪数据，而市场研究团队需要购买历史和用户偏好信息。两者都不需要访问用户名和密码。然而，由于所有这些数据都存储在同一个 ZFS 文件系统中，它们必须一起发送和接收。此外，数据所有者希望利用压缩、校验和和快照等功能，因此确实希望继续使用 ZFS 来存储和传输数据。遮蔽可以帮助他们做到这一点。

首先，他们会在源端对数据的一个快照创建两个克隆。在一个克隆中，他们创建市场研究团队希望看到的设置：删除用户名和密码文件，并用虚拟信息覆盖点击跟踪数据。在另一个克隆中，他们创建开发团队希望看到的设置：用虚假信息替换密码，并用随机生成的购买历史替换原来的购买历史。然后，他们会以父快照为基础创建一个遮蔽书签，使用两个克隆上的快照作为遮蔽快照。此后可以将父快照遮蔽后发送到研究团队和开发团队可访问的目标服务器。最后，可以从父快照向每个克隆分别发送增量流，并在目标服务器上接收；这些快照与源端上的完全相同，可以立即投入使用，而目标上的父快照则不包含源端存在的任何用户名和密码数据，因为这些数据已被遮蔽发送操作移除。

## 示例

### 示例 1：远程复制 ZFS 数据

以下命令先发送一个完整流，再发送一个增量流，发送到一台远程机器上，并分别恢复为 `poolB/received/fs@a` 和 `poolB/received/fs@b`。`poolB` 必须包含文件系统 `poolB/received`，而且初始时不得包含 `poolB/received/fs`。

```sh
# zfs send pool/fs@a | \
    ssh host zfs receive poolB/received/fs@a
# zfs send -i a pool/fs@b | \
    ssh host zfs receive poolB/received/fs
```

### 示例 2：使用 zfs receive -d 选项

以下命令向一台远程机器发送 `poolA/fsA/fsB@snap` 的完整流，并接收为 `poolB/received/fsA/fsB@snap`。所接收快照名称中的 `fsA/fsB@snap` 部分是根据所发送快照的名称确定的。`poolB` 必须包含文件系统 `poolB/received`。如果 `poolB/received/fsA` 不存在，则会被创建为一个空文件系统。

```sh
# zfs send poolA/fsA/fsB@snap | \
    ssh host zfs receive -d poolB/received
```
