# zfsconcepts(7)

## 名称

`zfsconcepts` — ZFS 概念概述

## 说明

### ZFS 文件系统层级

ZFS 存储池是为数据集提供空间的设备的逻辑集合。存储池同时也是 ZFS 文件系统层级的根。

池的根可以作为一个文件系统来访问，例如挂载与卸载、创建快照以及设置属性。但物理存储特性由 zpool(8) 命令管理。

有关创建与管理存储池的更多信息，参见 zpool(8)。

### 快照

快照是文件系统或卷的只读副本。快照的创建极其迅速，并且最初不占用池中的额外空间。随着活动数据集中数据的变化，快照消耗的空间会逐渐超过原本与活动数据集共享的部分。

快照可以使用任意名称。卷的快照可以被克隆或回滚，其可见性由父卷的 `snapdev` 属性决定。

文件系统快照可以通过文件系统根目录下的 `.zfs/snapshot` 目录访问。快照会按需自动挂载，并可能被定期卸载。在 Linux 上，`.zfs/snapshot` 下的条目无论快照当前是否已挂载，都会通过 statfs(2) 报告其快照的 fsid，因此无需挂载快照即可识别它：以 `O_PATH` 打开该条目（这不会触发自动挂载），然后对该描述符调用 fstatfs(2)，正如 NFS 服务器为解析未挂载快照的文件句柄所做的那样。`.zfs` 目录的可用性与可见性可由 `snapdir` 属性控制。

### 书签

书签与快照类似，也是文件系统或卷的只读副本。与快照相比，书签的创建同样极其迅速，且不占用池中的额外空间。书签也可以使用任意名称，与快照非常相似。

与快照不同，书签无法通过文件系统以任何方式访问。从存储的角度看，书签只是提供了一种把某个快照的创建时间点引用为独立对象的方式。书签最初与快照绑定，而不是与文件系统或卷绑定；即使快照本身被销毁，书签依然存在。由于书签非常轻量，几乎没有销毁它们的必要。

### 克隆

克隆是一种可写的卷或文件系统，其初始内容与另一个数据集相同。与快照一样，克隆的创建几乎是瞬时完成的，并且最初不占用额外空间。

克隆只能从快照创建。克隆快照时，会在父对象与子对象之间建立一种隐式依赖。即使克隆创建在数据集层级中的其他位置，只要克隆存在，原始快照就无法被销毁。`origin` 属性公开了这一依赖关系；若存在此类依赖，destroy 命令会将其列出。

克隆的父子依赖关系可以通过 promote 子命令反转。这会使“origin”文件系统变成指定文件系统的克隆，从而使得克隆最初源自的那个文件系统能够被销毁。

### 挂载点

创建 ZFS 文件系统是一项简单的操作，因此单个系统上的文件系统数量可能相当多。为此，ZFS 会自动管理文件系统的挂载与卸载，无需编辑 `/etc/fstab` 文件。所有自动管理的文件系统都会在系统启动时由 ZFS 挂载。

默认情况下，文件系统挂载在 `/path` 之下，其中 path 是该文件系统在 ZFS 命名空间中的名称。目录会按需创建与销毁。

文件系统也可以通过 `mountpoint` 属性设置挂载点。该目录会按需创建，并且在调用 `zfs mount -a` 命令时（无需编辑 `/etc/fstab`），ZFS 会自动挂载该文件系统。`mountpoint` 属性可以被继承：如果 pool/home 的挂载点为 `/export/stuff`，则 pool/home/user 会自动继承挂载点 `/export/stuff/user`。

若文件系统的 `mountpoint` 属性设置为 `none`，则该文件系统无法被挂载。

如有需要，也可以使用传统工具（mount、umount、`/etc/fstab`）管理 ZFS 文件系统。如果文件系统的挂载点设置为 `legacy`，ZFS 将不再尝试管理该文件系统，挂载与卸载由管理员负责。由于池必须先导入，legacy 挂载才能成功，管理员应确保仅在启动时的 zpool import 过程完成后再尝试 legacy 挂载。例如，在使用 systemd 的机器上，挂载选项 `x-systemd.requires=zfs-import.target` 可以确保在 systemd 尝试挂载文件系统之前 zfs-import 已经完成。详见 systemd.mount(5)。

### 去重

去重是在块级别移除冗余数据、从而减少总存储数据量的过程。如果文件系统启用了 `dedup` 属性，重复的数据块会被同步移除，其结果是仅存储唯一数据，公共组成部分在文件之间共享。

去重是非常消耗资源的操作。通常建议在启用去重时，每 1 TiB 存储空间至少配备 1.25 GiB 内存。精确的内存需求在很大程度上取决于池中存储的数据类型。

在规划不当的系统上启用去重可能导致性能问题（I/O 缓慢、管理操作缓慢），甚至可能因内存耗尽而导致存储池无法导入。去重会消耗大量处理器（CPU）与内存资源，并产生额外的磁盘 I/O。

在创建启用去重的池之前，请确保已合理规划硬件需求，并落实了适当的恢复措施（例如定期备份）。可以考虑使用 `compression` 属性作为资源消耗较低的替代方案。

### 块克隆

块克隆（block cloning）是一种允许文件（或文件的一部分）被“克隆”的机制，即创建浅拷贝：引用现有数据块而不进行实际复制。之后对数据的修改会触发该数据块的复制，并在副本上进行修改。该机制用于实现“reflink”或“文件级写时复制”。

被克隆的块记录在一个称为块引用表（Block Reference Table，BRT）的特殊磁盘结构中。与去重不同，该表的开销极小，因此可以始终保持启用。

同样与去重不同的是，克隆必须由用户程序发起。许多常用的文件复制程序（包括较新版本的 `/bin/cp`）会自动尝试创建克隆。更多信息请在这些程序的文档中查找“clone”“dedupe”或“reflink”。

块克隆存在一些限制：只能克隆完整的块；尚未写入磁盘的块、已加密的块，或源与目标 `recordsize` 属性不同的块，都无法克隆。操作系统可能施加额外限制，例如大多数版本的 Linux 不允许跨数据集克隆。
