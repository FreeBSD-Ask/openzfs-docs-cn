# zpoolconcepts(7)

## 名称

`zpoolconcepts` — ZFS 存储池概述

## 说明

### 虚拟设备（vdevs）

“虚拟设备”描述单个设备或一组按特定性能与故障特性组织的设备。支持以下虚拟设备：

#### `disk`

块设备，通常位于 `/dev` 之下。ZFS 可以使用单个 slice 或分区，但推荐使用整块磁盘。磁盘可以用完整路径指定，也可以用简写名称（即 `/dev` 下路径的相对部分）指定。省略 slice 或分区标识即表示整块磁盘。例如，`sda` 等价于 `/dev/sda`。给定整块磁盘时，如有必要，ZFS 会自动为磁盘打上标签。

#### `file`

常规文件。强烈不建议使用文件作为后备存储：它主要用于实验目的，因为文件的容错能力取决于其所在的文件系统。文件必须用完整路径指定。

#### `mirror`

两个或更多设备的镜像。数据以完全相同的方式复制到镜像的所有组件上。由 `N` 块大小为 `X` 的磁盘组成的镜像可容纳 `X` 字节，并能承受 `N-1` 个设备故障而不丢失数据。

#### `raidz`、`raidz1`、`raidz2`、`raidz3`

一种分布式校验布局，类似 RAID-5/6，但校验分布更优，且不存在 RAID-5/6 的“写洞”问题（即断电后数据与校验不一致）。数据与校验条带化分布在 raidz 组内的所有磁盘上，但条带宽度不一定一致。

raidz 组可以采用单重、双重或三重校验，分别意味着该组可以承受一、二或三个故障而不丢失任何数据。`raidz1` 表示单重校验的 raidz 组，`raidz2` 表示双重校验，`raidz3` 表示三重校验。`raidz` 是 `raidz1` 的别名。

由 `N` 块大小为 `X` 的磁盘、`P` 块校验盘组成的 raidz 组可容纳约 `(N-P)*X` 字节，并能承受 `P` 个设备故障而不丢失数据。raidz 组中的最少设备数为校验盘数加一。为提升性能，建议的设备数在 3 到 9 之间。

#### `draid`、`draid1`、`draid2`、`draid3`

raidz 的一种变体，提供内置的分布式热备盘，从而可以更快地 resilver，同时保留 raidz 的优点。dRAID vdev 由多个内部 raidz 组构成，每组有 `D` 块数据盘与 `P` 块校验盘。这些组分布到所有子设备上，以充分利用可用的磁盘性能。

与 raidz 不同，dRAID 使用固定条带宽度（必要时用零填充），以支持完全顺序化的 resilver。这一固定条带宽度会显著影响可用容量与 IOPS。例如，使用默认的 `D=8` 与 4 KiB 磁盘扇区时，最小分配大小为 32 KiB。若使用压缩，这一相对较大的分配大小会降低有效压缩比。在使用 ZFS 卷（zvol）与 dRAID 时，`volblocksize` 属性的默认值会相应增大，以匹配分配大小。如果 dRAID 池将存放大量小块数据，建议同时添加一个镜像的 `special` vdev 来存放这些块。

在 I/O 方面，由于任意读取都必须访问全部 `D` 块数据盘，其性能与 raidz 类似。可交付的随机 IOPS 大致可估计为 `floor((N-S)/(D+P))*single_drive_IOPS`。

与 raidz 一样，dRAID 可以采用单重、双重或三重校验。可使用 `draid1`、`draid2`、`draid3` 类型指定校验级别。`draid` 是 `draid1` 的别名。

由 `N` 块大小为 `X` 的磁盘、每个冗余组 `D` 块数据盘、校验级别 `P`、`S` 块分布式热备盘组成的 dRAID，可容纳约 `(N-S)*(D/(D+P))*X` 字节，并能承受 `P` 个设备故障而不丢失数据。

#### `draid[:data d][:children c][:width w][:spares s]`

可以通过在 `draid` 关键字后附加以下一个或多个可选参数来指定非默认的 dRAID 配置：

* `parity`：校验级别（1-3）。
* `data`：每个冗余组中的数据盘数量。一般而言，`D` 取值越小，IOPS 越高、压缩比越好、resilver 越快，代价是总可用容量减少。默认为 `8`，除非 `N-P-S` 小于 `8`。
* `children`：预期的子设备数量。在列出大量设备时可用作交叉校验；若提供的子设备数量不符会返回错误。
* `width`：可以在同一行中配置多组子设备，此时 `width` 是 `children` 的倍数。此类配置允许创建故障组：每组中的第 i 个设备来自不同的故障域（例如不同的机箱），这样即使某个域中的全部设备故障，`draid` vdev 仍能凭借足够的冗余继续运行并重建数据。对于 `draid2`，同一时间可以有两个域故障；对于 `draid3`，可以是三个域（前提是任何故障组内没有其他故障）。每组只允许出现一、二或三个故障。
* `spares`：分布式热备盘的数量。所有热备盘在故障组之间共享。默认为零。

注意：为支持域故障，任何故障组内的故障数都不能超过 `parity-1`，无论故障设备是否已重建到 dRAID 热备盘上——因为这些热备盘的块可能被映射到故障域中的设备上，所以任何故障组内可容忍的故障数都不能超过 `parity`。

#### `spare`

一种伪 vdev，用于跟踪池中可用的热备盘。更多信息参见“热备盘”一节。

#### `log`

独立的意图日志设备。如果指定了多个日志设备，写入会在这些设备之间做负载均衡。日志设备可以做镜像。但意图日志不支持 raidz 类型的 vdev。更多信息参见“意图日志”一节。

#### `dedup`

专用于去重表的设备。该设备的冗余度应等于或高于池中其他普通设备的冗余度。如果指定了多个 dedup 设备，分配会在这些设备之间做负载均衡。

#### `special`

专用于分配各类内部元数据、并可选择存放小文件块的设备。该设备的冗余度应等于或高于池中其他普通设备的冗余度。如果指定了多个 special 设备，分配会在这些设备之间做负载均衡。

有关 special 分配的更多信息，参见“special 分配类”一节。

#### `cache`

用于缓存存储池数据的设备。缓存设备不能配置为镜像或 raidz 组。更多信息参见“缓存设备”一节。

#### `fdomain`、`failure_domain`

表示 dRAID vdev 的故障域设备列表。

#### `fgroup`、`failure_group`

表示 dRAID vdev 的故障组设备列表。

虚拟设备不能任意嵌套。镜像、raidz 或 draid 虚拟设备只能由文件或磁盘创建。不允许镜像的镜像或其他类似组合。

一个池在配置顶层可以有任意数量的虚拟设备（称为“根 vdev”）。数据会在所有顶级设备之间动态分布，以平衡各设备上的数据量。随着新虚拟设备加入，ZFS 会自动把数据放到新可用的设备上。

虚拟设备在命令行中逐个指定，以空白分隔。像 `mirror` 和 `raidz` 这样的关键字用于区分一个组的结束与另一个组的开始。例如，以下命令创建一个拥有两个根 vdev、每个都是两块盘镜像的池：

```sh
# zpool create mypool mirror sda sdb mirror sdc sdd
```

### 设备故障与恢复

ZFS 提供了一整套处理设备故障与数据损坏的机制。所有元数据与数据都带校验和，检测到损坏时，ZFS 会自动从完好的副本修复坏数据。

要利用这些特性，池必须使用某种形式的冗余，即使用镜像组或 raidz 组。虽然 ZFS 支持在非冗余配置下运行（每个根 vdev 只是一块磁盘或一个文件），但强烈不建议这样做：一次位翻转就可能导致你的部分或全部数据不可用。

池的健康状态由三种状态之一描述：`online`、`degraded` 或 `faulted`。online 池的所有设备均正常工作。degraded 池中有一个或多个设备故障，但由于配置具有冗余，数据仍然可用。faulted 池的元数据已损坏，或者有一个或多个设备故障且副本不足以继续运行。

顶级 vdev（如镜像或 raidz 设备）的健康状况可能受其关联 vdev 或组件设备状态的影响。顶级 vdev 或组件设备处于以下状态之一：

#### DEGRADED（降级）

一个或多个顶级 vdev 因一个或多个组件设备离线而处于降级状态。仍有足够的副本以继续运行。

一个或多个组件设备处于降级或故障状态，但仍有足够的副本以继续运行。其底层情形如下：

* 校验和错误或慢速 I/O 的数量超出可接受水平，设备被降级以提示可能存在问题。ZFS 仍会按需继续使用该设备。
* I/O 错误的数量超出可接受水平。由于副本不足以继续运行，该设备无法被标记为故障。

#### FAULTED（故障）

一个或多个顶级 vdev 因一个或多个组件设备离线而处于故障状态。副本不足以继续运行。

一个或多个组件设备处于故障状态，且副本不足以继续运行。其底层情形如下：

* 设备能够打开，但内容与预期值不符。
* I/O 错误的数量超出可接受水平，设备被标记为故障，以防止继续使用。

#### OFFLINE（离线）

该设备已被 `zpool offline` 命令显式下线。

#### ONLINE（在线）

该设备在线并正常工作。

#### REMOVED（已移除）

该设备在系统运行期间被物理移除。设备移除检测取决于硬件，并非所有平台都支持。

#### UNAVAIL（不可用）

该设备无法打开。如果导入池时某设备不可用，由于该设备的路径从一开始就不正确，将改用唯一标识符来标识它。

校验和错误指磁盘返回了本应正确、实际却不正确的数据——换言之，是静默数据损坏的实例。校验和错误会在 `zpool status` 与 `zpool events` 中报告。当块以冗余方式存储时，受损的块可以被重建（例如利用 raidz 校验或镜像副本）。此时 ZFS 会把校验和错误记在包含受损数据的磁盘上。如果块无法重建（例如 raidz2 组中有 3 块盘受损），就无法确定是哪些磁盘发生了静默损坏，这种情况下，块所在的全部磁盘都会被报告校验和错误。

如果设备被移除后又重新接入系统，ZFS 会尝试自动将其恢复上线。设备接入检测取决于硬件，并非所有平台都支持。

### 热备盘

ZFS 允许把设备作为“热备盘”关联到池。这些设备不主动参与池的使用；但当某个活动设备故障时，它会自动由热备盘替换。要创建带热备盘的池，请指定一个包含任意数量设备的 `spare` vdev。例如：

```sh
# zpool create pool mirror sda sdb spare sdc sdd
```

热备盘可以在多个池之间共享，可以用 `zpool add` 命令添加、用 `zpool remove` 命令移除。一旦启动热备盘替换，配置中就会创建一个新的 `spare` vdev，并一直保留到原设备被更换为止；此时若有其他设备故障，热备盘可以再次投入使用。

如果池有一个正在被使用的共享热备盘，则该池无法导出，因为其他池也可能使用这一共享热备盘，从而可能导致数据损坏。

共享热备盘会带来一定风险：如果这些池导入在不同的主机上，且两个池同时发生设备故障，它们可能同时尝试使用该热备盘。这种情况可能无法被检测到，从而导致数据损坏。

正在进行的替换可以通过分离该热备盘来取消。如果分离的是原先故障的设备，则热备盘会取代它在配置中的位置，并从所有活动池的热备盘列表中移除。

`draid` vdev 类型提供分布式热备盘。这些是虚拟设备：它们的块被保留并分布到所有真实设备上，因此 resilver 到它们上会快得多，因为不再有单个设备成为瓶颈。快速 resilver 对数据持久性至关重要，它缩短了池中数据冗余处于降级状态的时间，从而降低了一次性失去更多设备而无法承受的概率。dRAID 热备盘以其所属的 draid vdev 命名（`draid1-2-3` 表示 vdev `2` 的第 `3` 块热备盘，该 vdev 为单重校验 dRAID），并且只能由该 dRAID vdev 使用。除此之外，它们的行为与普通热备盘相同。

热备盘不能替换日志设备。

### 意图日志

ZFS 意图日志（ZIL）满足 POSIX 对同步事务的要求。例如，数据库通常要求系统调用返回时其事务已位于稳定存储设备上。NFS 及其他应用程序也可以使用 fsync(2) 来确保数据稳定。默认情况下，意图日志从主池内的块中分配；但使用独立的意图日志设备（如 NVRAM 或专用磁盘）可能获得更好的性能。例如：

```sh
# zpool create pool sda sdb log sdc
```

也可以指定多个日志设备，并且它们可以做镜像。多个日志设备做镜像的示例见 zpool(8) 的“示例”一节。

### 缓存设备

可以把设备作为“缓存设备”添加到存储池。这些设备在主内存与磁盘之间提供额外一层缓存。对于读取密集型工作负载，当工作集大小远大于主内存所能缓存的数据量时，使用缓存设备可以让更多工作集由低延迟介质提供。对于内容大多为静态的随机读取工作负载，使用缓存设备带来的性能提升最大。

要创建带缓存设备的池，请指定一个包含任意数量设备的 `cache` vdev。例如：

```sh
# zpool create pool sda sdb cache sdc sdd
```

缓存设备不能做镜像，也不能是 raidz 配置的一部分。如果在缓存设备上遇到读取错误，该读取 I/O 会被重新发往原存储池设备，而后者可能属于镜像或 raidz 配置。

缓存设备的内容在重启后仍然保留，并在导入池时以 L2ARC 形式异步恢复（持久化 L2ARC）。可以通过设置 `l2arc_rebuild_enabled=0` 禁用该行为。对于小于 1 GiB 的缓存设备，ZFS 不会写入重建 L2ARC 所需的元数据结构，以节省空间；这可以通过 `l2arc_rebuild_blocks_min_l2size` 更改。即使不写入任何元数据结构，缓存设备头（512 B）仍会被更新。

L2ARC 根据缓存总容量以两种模式之一运行。当 L2ARC 总容量小于 `arc_c_max` 的两倍时，L2ARC 在缓冲区被从 ARC 淘汰时将其写入缓存。当总容量至少为 `arc_c_max` 的两倍时，L2ARC 使用持久标记来跟踪各轮扫描位置，在写入吞吐允许时写入可缓存内容。深度上限 `l2arc_ext_headroom_pct` 限制标记从队尾推进的距离，使其专注于即将被淘汰、缓存收益最大的缓冲区。

如果通过 `zpool add` 添加缓存设备，其标签与头部会被覆盖，内容也不会在 L2ARC 中恢复，即使该设备此前曾属于该池。如果通过 `zpool online` 将缓存设备上线，其内容会在 L2ARC 中恢复。这在内存压力较大、缓存设备内容无法完整恢复到 L2ARC 时很有用：用户可以在内存压力较小时把缓存设备下线再上线，以将其内容完整恢复到 L2ARC。

### 池检查点

在开始包含破坏性操作的关键流程（如 `zfs destroy`）之前，管理员可以为池的状态创建检查点；一旦出现失误或故障，就可以把整个池回退到该检查点。否则，在流程成功完成后可以丢弃该检查点。

池检查点可以视为整个池范围的快照，应谨慎使用，因为它包含池状态的所有部分——从属性到 vdev 配置。因此，池存在检查点时，某些操作不被允许：具体来说，vdev 的移除/附加/分离、镜像拆分以及更改池的 GUID。添加新 vdev 是支持的，但如果回退，则必须重新添加。最后，使用该功能的用户应记住：存在检查点的池执行 scrub 不会修复已进入检查点的数据。

为池创建检查点：

```sh
# zpool checkpoint pool
```

要稍后回退到检查点状态，需要先导出池，然后在导入时回退：

```sh
# zpool export pool
# zpool import --rewind-to-checkpoint pool
```

请注意，回退到检查点会**永久丢弃**它。一旦用上述回退命令成功导入池，就无法再回退到同一个检查点。

丢弃池的检查点：

```sh
# zpool checkpoint -d pool
```

检查点存在期间，数据集预留（由 `reservation` 与 `refreservation` 属性控制）可能无法强制执行，因为检查点被允许消耗数据集的预留空间。最后，属于检查点但已在池的当前状态中被释放的数据，在 scrub 期间不会被扫描。

### special 分配类

special 类别中的分配专用于特定的块类型。默认情况下包括所有元数据、用户数据的间接块、意图日志（在没有独立日志设备时）以及去重表。该类也可以按数据集粒度配置为接纳小文件块或 zvol 块。

在把其他设备分配到 special 类别之前，池必须始终至少有一个普通（非 `dedup`/`special`）vdev。如果 `special` 类别写满，原本要进入它的分配会回退到普通类别。

可以通过取消设置 `zfs_ddt_data_is_special` ZFS 模块参数，把去重表排除在 special 类别之外。

把小文件块或 zvol 块纳入 special 类别是可选的。每个数据集都可以通过把 `special_small_blocks` 属性设置为非零值，来控制允许进入 special 类别的小文件块的大小。有关该属性的更多信息，参见 zfsprops(7)。
