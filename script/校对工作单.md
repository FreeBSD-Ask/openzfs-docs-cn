## 六、批次执行规则（各批次代理通用）

1. 动手前完整阅读 AGENTS.md 与 shu-yu-biao.md，术语一律以术语表为准。
2. 逐段逐句对照原文：查事实性错误、漏译、机翻腔、用词不当、版本过时、语法/文字错误、欧化汉语。
3. 逐处 Edit 修改，禁止 sed/awk/python 批量替换；每处修改前确认问题属实，修改后复核。
4. 红线：不改 H1；不改代码块内容（仅可译代码块内英文注释）；不改版本号、用户名、邮箱、URL、IP、消息 ID、带圈数字；不译 fstab 等配置内容。
5. 校对两轮：第一轮逐段查错并修改；第二轮全文复查（改动准确性、无遗漏、无新问题）。
6. 修改后对所改文件运行 `markdownlint-cli2 "<文件>" --config .github/.markdownlint.json`，清零自引入的错误。
7. 每批将修改明细写入 `script/proofread-logs/<批次名>.md`（文件、原句 → 新句、原因），末尾统计：修改处数/页数/遗留问题。
8. 只允许修改本批次分配的文件与自己的日志文件；SUMMARY.md 一律不改（由主会话统一维护）。
9. **代理不执行 git 操作**；主会话在每批完成并复核后立即提交（自动 git、每批一次提交，提交信息格式：`校对：<批次名> <简述>` 或 `man：<批次名> <简述>`），保持高提交频次。
10. **禁止并发子代理（2026-10-19 用户指令）**：同一时间只允许一个后台代理运行；派发前确认上一个已完成。中断的批次用 SendMessage 恢复原代理继续（上下文仍在），不要新开代理。
